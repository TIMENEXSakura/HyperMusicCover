# 第三轮：胶囊实际入口回归修复

本轮只修复实际页面／操作入口，并按要求将“词”的完整停留时间调整为 300 ms。导航图标反色已经由用户真机确认正常，本轮不改图标实现；歌词来源设置、TTML／和声、字号、颜色和联网控制均保持原实现。仍须用户真机验收通过后，按功能分别提交中文 PR。

## 源码原因与修改

| 问题 | 证据与处理 | 文件 |
| --- | --- | --- |
| 音乐胶囊有提示、歌词透明 | `MediaCard.setCardProgressFrom()` 在非封面模式将进度归零，`LyricView.showTarget()` 又将此值用于独立歌词页。改用歌词页自身进度：独立页为 1，封面页仍跟随媒体卡。原有歌词可用性、时钟、控制中心、解锁和容器透明度门控保留。 | `lyrics/LyricView.java`、`lyrics/LockLyrics.java`、`lyrics/LyricPageVisibility.java` |
| 重建时错误裁切区域 | 附着但尚未布局的零尺寸媒体卡不能提供有效下边界，改走原有记录值／默认值回退。 | `lyrics/LockLyrics.java` |
| 计时器／闹钟没有实际操作入口 | 原 CLOCK 分支先打开只有表盘和常亮开关的 CountdownScene，跳过实际功能入口；其后读取 `row.mOnClickListener` 也没有复用上游针对折叠行 flow 丢弃事件的处理。现在复用 `getInjector().clickListener`，由系统处理功能启动和必要认证；无可用入口时再尝试已有 contentIntent，最后请求对应单条原生卡片。没有猜测 Activity，也不发送暂停／结束命令。 | `island/MiniPlayerController.kt` |
| 导航提示不能证明页面出现 | 原入口仅记录打开请求就返回成功。打开时现在主动恢复 Host 容器、触发正常页面准备；区分请求、内容、附着、shown 和 fade。页面尚未显示时提示“正在打开导航界面”，沿已有帧观察器确认实际呈现后才替换成“已进入”；新点按、视图换绑、熄屏和销毁取消旧反馈，不新增长轮询或延迟成功回调。同步回调或异常不能把失效的 sceneKey 恢复成已打开。 | `immersive/ImmersiveHost.java`、`island/LockIslands.kt`、`island/MiniPlayerController.kt` |
| “词”太短 | 完整可见阶段由 100 ms 延长到 300 ms，再过渡至对勾。仍是单个可反向打断的时间线，整个提示 1300 ms；真实播放状态和歌词切换不依赖动画完成。 | `island/CapsuleFeedbackState.kt`、`island/PressFeedbackButton.kt` |

音乐的透明度阻断和 CLOCK 的入口问题已由源码确认。导航没有发现相同的恒零透明度问题；容器恢复和请求／呈现区分属于已确定的链路缺口，但**不能据此断言已复现并解决本机导航界面不出现的唯一根因**。仍须检查高德运行框架回报、远端页面就绪与真实绘制。

## 验证

- 本地独立 JVM：120 项通过，包含 4 项新增歌词页进度回归，以及“词”完整停留 300 ms 的边界验证。既有 TTML、LRC、和声、优先级与回退、动画打断、取消触摸测试保留。
- Android 编译、全量单元测试和 lint 由 GitHub Actions 验证，结果待本轮云构建回填。
- 未在当前环境安装 APK、自动操作锁屏或运行 SystemUI 真机测试。纯状态测试不等于 Android 触摸分发、Intent 启动或页面像素已经验证。

## 真机验收与必要日志

1. 音乐主体点击后必须真正出现歌词，媒体卡保持折叠；再点立即隐藏。分别在“词”、对勾及恢复阶段反向点击，最后状态一致。播放按钮只控制播放，上滑仍打开原面板。
2. 换歌、锁屏重建、熄屏唤醒后重复操作；检查歌词有实际文字、没有裁切且释放时钟占用。“词”完整停留 0.3 秒。
3. 高德导航点击后检查地图／导航内容真的出现、再点关闭显示而实际导航继续；上滑仍打开对应面板。等待远端页面时允许显示“正在打开”，不能把它当验收成功。图标仍保持已确认的正常颜色。
4. 闹钟／计时器点击应进入通知定义的功能入口，必要时先由系统要求解锁。没有可用直接入口时，单条原生卡片应提供该通知实际按钮；检查暂停／继续等操作可见、可用。
5. 快速点按、取消触摸、上滑及播放按钮不应互相触发；本轮未重写已存在的手势状态机。

若仍出现“只有动画”，请给出胶囊类型、大小胶囊、点击还是上滑，以及同次操作的模块 `mini` 诊断。音乐加 `lyricstate`（重点 `cardP/pageP`、`band`、`attached` 和 `show`）；导航加 `immersive state`、`MCImmersive: open result`、`shown/hidden` 与高德版本／导航方式（步行、骑行、驾车或公交）。时钟检查 `clock entry:` 后是 `notification clicker invoked`、`content intent sent` 还是 `requesting native card`。不需要通知正文、歌词正文、目的地或位置轨迹。

## 中文 PR 描述草稿（分别提交）

### 修复音乐胶囊独立歌词页透明及反馈停留时间

音乐胶囊直接打开歌词时，媒体卡仍折叠，旧渲染逻辑因此始终得到 0 透明度。独立歌词页现在使用自己的显示进度，封面模式继续跟随媒体卡，并保留原有锁屏显示门控与布局回退。反馈中的“词”完整停留 300 ms 后再过渡到对勾，支持中途反向切换。新增独立页、关闭重开、封面交接与停留时长回归测试。实际设备验收记录待补。

### 修复闹钟／计时器胶囊直接操作入口

CLOCK 胶囊现在复用系统通知注入器的 NotificationClicker，保留锁屏认证，并按已有 contentIntent、单条原生卡片回退。移除以只有倒计时显示的页面冒充完整操作界面的分支，避免折叠通知行的普通点击 flow 丢弃操作。实际设备验收记录待补。

### 修复导航胶囊打开请求与页面呈现的状态区分

直接打开沉浸页面时主动恢复 Host 容器并请求准备；打开状态在同步回调前发布，失败后回滚。反馈区分正在打开与实际呈现，新增不含位置或通知正文的诊断。导航图标和真实导航会话不变。远端服务／真机验证待补，不能仅凭构建成功提交为已验证修复。
