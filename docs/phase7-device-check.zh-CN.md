# 第七轮：歌词上下抽动、导航始终白字与整组手势反馈

本轮基于 Plus6。用户确认剩余问题是歌词打开时上下抽动，以及浅色导航地图上的歌词仍为白色；随后要求点按／上滑都整组从下方弹入，上拖时根据速度有限缩小并恢复。保留此前歌词来源、TTML／和声、外观配置、导航图标、页面保留与胶囊提示行为。

## 源码定位与修改

### 上下抽动与整体入场

Plus6 固定了媒体卡参考下边界，但歌词上边界仍来自正在收起的时钟。胶囊页面进度立即可用后，歌词进入期间又随时钟边界重算布局中心，暴露出位置移动。另一个初始化问题是首帧先增加显示进度、再判断是否需要立即适配行组尺寸；较高的和声／重叠组可能先出现，再缩到最终尺寸。

- `ClockCollapse.java` 提供同一次时钟计算的最终收起边界；只读目标不改变时钟动画，新进入／释放时清除旧值。
- `LyricView.java` 使用目标边界决定阅读位置；正在移动的时钟与媒体卡只裁剪上下边缘。首次可见前完成行组尺寸适配，不把首次显示当作换句缩放。
- `LockLyrics.prepareCapsulePresentation()` 接入 `Main.miniPlayerEnterCover()` 和反向入场路径。点按与上滑统一为整组从下方最多 36dp 进入，入场缩放从 0.94 恢复至 1；最终阅读位置仍在中上部。旧胶囊原点 POP 不再叠加到新动画上。新的普通封面入口清除胶囊展示标记，关闭过程本身仍保留反向动画，不让新效果串到其他入口。
- 快速关闭／重开沿当前显示进度反向，主歌词、和声、间奏点和正在退场的行共用一次整体变换；不逐行启动入场。裁剪和边缘渐隐使用变换后的实际位置，避免缩小后边缘行被提前跳过。

### 上拖速度反馈

`MiniPlayerRuntime.kt` 从真实 MotionEvent 观察音乐胶囊、右侧小球和原生媒体卡的速度，使用 dp/s 消除密度差异。`CardTouch.java` 只补观察入口，不消费事件或改写原有面板操作。

`LyricGestureFeedback` 将新增整组缩放限制在 **0.86–1**；越快上拖，缩小反馈越强。入场缩放与手势缩放合成后也不低于 0.86。松手、取消、多指、新手势、异常坐标、视图销毁均清理观察状态；120ms 没有新的移动时开始恢复。没有新增定时动画队列，反向和连续手势从当前尺寸继续。隐藏停用但尚未拆除的歌词窗口停止动画帧，重新接入时清理中断的手势缩放。原有系统的解锁／AOD 父容器变换与长和声的排版适配保持原逻辑，0.86 限制针对本次新增的交互反馈。

新增测试覆盖速度大小、密度、取消／反向、连续手势、不同刷新率、大时间间隔、极端速度与非有限值。`LockLyrics.onGestureFeedback()` 只唤醒现有歌词绘制，不重新创建歌词窗口或刷新封面。

### 导航始终白字

本环境可读取的 `/system/build.prop` 显示 Android 17／SDK 37。官方 Android 17 源码中，旧 `ScreenCapture` 的图层捕获类型已迁至 `ScreenCaptureInternal`，保护内容的布尔设置也改为整数策略。Plus6 只查找旧类型，异常后又永久设置不支持标志；这条源码路径会使地图采样一直未知，随后使用白色回退。不是将明亮像素故意对应成白色，也不能靠交换黑白修正。

依据：[Android 17 ScreenCaptureInternal](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android17-release/core/java/android/window/ScreenCaptureInternal.java)、[Android 17 ScreenCapture 策略定义](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android17-release/core/java/android/window/ScreenCapture.java)。当前环境无法直接执行 Android 原生 su／读取运行中的模块日志，因此实际 ROM 是否还有其他捕获限制仍需真机确认。

- `NavigationCaptureApi.java` 探测完整图层捕获契约，适配 Android 15／16 旧接口与 Android 17 新接口，不调用整屏捕获接口。隐藏成员沿用项目现有的单成员查找方式，初始化放在工作线程，不全局改变 SystemUI 隐藏 API 策略。
- `NavigationSurfaceContrast.java` 仍只采导航远端 Surface 子树，读取小尺寸像素并统计明暗占比。亮像素占多数选择黑字，暗像素占多数选择白字；既有稳定性与颜色渐变保留。
- 安全／受保护内容不请求读取；Android 17 设置遇到此类内容时失败，旧接口排除后也检查安全内容标记，避免将被遮黑的画面算成真实暗地图。
- 初始化失败可在 30 秒后重试；超时允许一次替代捕获，但 `NavigationCaptureSlots` 将未完成的原生请求硬限为 2 个，晚到结果仍释放资源，不能无限排队。
- `LyricContrastBackground`、`ImmersiveHost` 与 `Main` 同时区分“地图已请求”和“地图已显示”。地图等待图层时保持地图来源，不落入封面取色，也不因这时点击歌词而让地图向封面让位。`LiveAlertScene` 提供准备好的只读采样句柄与状态。

初次有效样本到达前仍使用临时颜色；采样失败会明确标记未知，不能把白色回退称为采样成功。实际地图颜色、导航方向图标及用户保存的歌词配色均不改写。

## 真机待测

1. 同一首歌点按打开、关闭、再次打开，以及从胶囊上滑进入：歌词整组由下方进入，最终位置稳定，不上下抽动；与现有封面进入同步。
2. 已显示歌词时慢拖、快拖、反向、松手、取消、连续拖动：整组缩放有限且恢复，不逐句出现，不影响播放按钮或面板行为；媒体卡上升仍遮去下方歌词，收起后页面保留。
3. 高和声／重叠长行、HDR 开关、不同字号、现成导航小钟、保留壁纸模式、熄屏与视图重建下重复前两项。
4. 浅色地图应使用黑字，深色地图使用白字；系统主题与地图日夜模式不一致时也按地图像素选择。地图切换后等待至少两个采样周期，确认渐变和稳定性。
5. 地图刚请求、尚未载入时打开歌词，不能被封面抢占。导航／媒体面板展开收起仍保留原页面，已正常的方向图标着色保持正常。

取色日志观察 `MCLyricContrast`：先应出现 `api-ready=android.window.ScreenCaptureInternal`，随后出现 `pixels … bright/… dark/… total -> black|white`。`source=map candidate=unknown` 表示没有有效结果；失败包含 SDK、阶段、根异常、视口／裁剪／缓冲区尺寸及页面状态，不记录地图内容或位置。抽动问题查看 `lyricstate` 中 `layoutClock`、`clipTop`、`band`、`groupEntry` 和 `gestureScale`。
