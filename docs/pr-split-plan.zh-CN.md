## 拆分原则

第七轮 `7fd41cc` 针对 Plus6 的上下抽动与导航始终白字补修，并按新反馈增加整组入场／上拖缩放，已通过 403 项云端测试及 release／lint 检查，仍待真机验收，详见 [第七轮说明](phase7-device-check.zh-CN.md)。Android 17 图层接口兼容性修正归入黑白歌词 PR，不单独复制整套导航集成。

第六轮 `d072470` 继续修复第五轮真机反馈，并补充媒体／导航面板收起后的页面保留，已通过 383 项云端测试及 release／lint 检查，详见 [第六轮验收说明](phase6-device-check.zh-CN.md)。实际地图图层采样仍需验证 ROM 支持；该轮不改变“用户验收后再分功能提交”的顺序。

- 当前 `fix/lyrics-and-capsule-controls` 仅用于集成测试。测试通过后，从届时上游最新版本建立各功能分支，逐项选择变更并重新验证，不能直接把整合提交 cherry-pick 到每个分支。
- 每个 PR 只含本功能的实现、资源、必要测试及中文说明。主歌词与和声字号属于同一项独立外观功能；主唱／和声转换与对应渲染修复需保持一致，放在同一个修复 PR。
- 共享的配置传递、来源策略和胶囊点按分派按最先需要的功能引入最小接口，后续 PR 扩展。若后一个 PR 必须依赖前一个，则待前者合并后更新基线再提交，避免在多个 PR 中重复整段修改。
- 测试迁包等基础维护变更单独整理，不能借功能 PR 混入无关行为变化。继承自旧分支、与用户功能无关的修改也需排除或另行讨论。
- 中文 PR 说明写明具体触发条件、修改后的行为、构建／回归结果与真机验证范围；尚未验证的部分明确列出，不复制整合说明来夸大每个 PR 的范围。
- 未经用户测试确认，不创建任何上游 PR。
