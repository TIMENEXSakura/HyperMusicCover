# 第八轮：歌词首帧、时钟遮挡、无歌词反馈与导航交接

基于上轮 `7fd41cc` 集成代码，处理用户继续反馈的歌词上闪和拖动时导航小球消失，并加入时钟遮挡独立开关、无歌词问号反馈，修复导航退出背景、缩小关闭叉号及加快地图取色。保留 TTML／和声、来源顺序、联网控制、字号配色、整组下方入场和 0.86–1 手势缩放。

## 修改与原因

| 问题 | 已确认的源码路径 | 本轮修改 |
| --- | --- | --- |
| 胶囊歌词打开时上闪 | `LyricView.step` 在有效 band 未出现时已经初始化 focus/anchorFix；首个有效 band 到来后把差值加入 scroll，再回弹到行目标。首次分支另有先写 focus 再判断 focus<0 的问题。 | `LyricView` 等有效布局后才定位，首个可见帧同步安放 anchor/scroll/fit，不从不可见的旧位置回弹。换句与实际快进动画保留。 |
| 入场受时钟遮挡 | 上边缘 clip 随实际移动时钟变化；`ClockCollapse` 从 ENTER 切到 ON 的瞬间又切回上一帧实际时钟位置。 | ENTER/ON 共用目标缓存，首个 ON pose 写完后更新；宿主、尺寸、设置和重建会失效。新增开关控制移动时钟 clip，最终排版与媒体卡底部裁剪继续保留。 |
| 导航小球在音乐拖动中消失 | `prepareGroupUnsafe` 已令其他通知留在胶囊中，`g.other=null`；旧 `groupShowsSmall` 却把未由动画接管的小球隐藏。 | `MiniPlayerPresentationPolicy` 按实际绘制所有权决定隐藏；音乐大胶囊变形时，旁边导航小球保留。 |
| 拖动结束后整行短暂消失 | morph/group 清理后没有重算胶囊列表，旧音乐位置叠加 nativeRequested 导致整行关闭，等待下次外部 refresh 才恢复。 | `MiniPlayerController.morphListener.onSettled` 先 refresh 稳定位置与绑定，再更新显隐；取消及反向落地走同一清理。 |
| 没有歌词仍提示开启 | 点按返回的是页面请求意图，反馈未核对当前曲目的获取结果；旧 `hasLyrics` 还包含上一曲的展示保持状态。 | 新 `LyricAvailability` 只读取当前曲 lines/cache/loading/park/settle。等待只画“词”，所有来源无可用结果才绘制问号，不额外发网络请求。 |
| 导航关闭后背景透明 | 导航上的歌词覆盖标记被隐藏歌词清掉，导航 close/readyChanged 没有恢复音乐背景的交接。 | `NavigationLyricBackground` 单独保存背景恢复意图；`Main`/`ImmersiveHost` 在导航进入及关闭时交接，按当前歌曲与原背景设置恢复，不重新开启已隐藏歌词。 |
| 导航反色偏慢 | 首次 Surface 未就绪后也等完整 1500ms；反向明暗确认也等下一次稳态采样。 | 入场前 2 秒就绪检查间隔为 100ms，正常采样改 1000ms，明显反向明暗在 250ms 再确认；保留两次多数判定及颜色渐变。就绪检查不捕获像素，原请求并发上限仍生效。 |

源码缺陷能够复现逻辑问题，但当前无法直接验证这台 ROM 的所有实际绘制顺序，不能据此声称真机抽动已完全消失。没有改变已正常的导航方向图标染色，也没有为歌词窗口增加不透明背景或触摸拦截。

## 设置与反馈

- 新设置“歌词动画不受时钟遮挡”，默认开启，沿用 `FeaturesPage` 的 MIUIX `SwitchPreference`。`ModuleBridge` → `ProbeReceiver` → `LockLyrics.setClockIndependentMotion` 实时接入；`ModuleState` 保存/读取，`SettingsBackup` 导入/导出，状态键 `lyricclockindependent`。仅胶囊歌词的动态时钟裁剪受此开关影响，首帧定位修复始终生效。
- `PressFeedbackButton` / `CapsuleFeedbackState` 的无歌词反馈：绘出“词”后按路径绘问号曲线和圆点，完成停留 300ms 后恢复实时播放图标。关闭叉号范围内缩 8%，线宽由 2.2dp 改为 1.7dp。
- `LyricFeedbackRequest` 绑定点击请求代次、会话、歌曲、歌词 key、视图实例和视图绑定代次。旧曲结果、同一视图 A→B→A 重绑、关闭和新点击不能完成旧提示；动画可从当前帧被打断。
- 确认无歌词的当前曲再次点击仍显示问号。取消未终结的查找不会伪报无歌词；缓存有词的正常关闭保留叉号。
- 背景交接覆盖两种顺序：导航→打开歌词→隐藏歌词→退出导航；打开歌词→导航→隐藏歌词→退出导航。恢复封面／模糊／保留壁纸取决于原设置和当前显隐，不改写歌曲或导航应用的状态。

## 真机验收

1. 多次点击胶囊打开／关闭歌词、从胶囊上滑进入，含高和声/长行：歌词整组由下方进入，不先上闪；快速反向保持当前位置连续，媒体卡仍只遮去下方内容。
2. 分别开启/关闭新时钟开关，重启 SystemUI、重新进入设置、导出/导入配置，确认选择保留且实际裁剪不同。开启时，时钟运动不裁掉歌词；最终阅读位置不应被改变。
3. 音乐在大胶囊、导航在右侧小球时，慢拖、快拖、取消、上滑落地、下滑返回；导航入口始终留在屏幕可用位置，落地后可点击/上滑。音乐位于小球的相反布局也需验收。
4. 选一首确认无可用歌词的媒体，点击应显示词与逐步绘出的问号；重复点击、加载中换歌、快速关开、新歌立即有缓存、视图重建后，没有旧问号或旧开启提示残留。
5. 检查关闭叉号大小、300ms 完成停留和播放/暂停恢复；实际播放状态变化不应被提示改写。
6. 两种导航/歌词开关顺序下关闭导航 UI，原背景恢复且隐藏歌词仍隐藏；保留壁纸、封面、模糊模式都要覆盖。
7. 进入浅色/深色地图及切换地图日夜模式，反色更及时但不反复闪烁，已正常方向图标仍正常。

首次定位诊断：`[MCLyric]` 的 `placement start/frame1/frame2/frame3`（每 request/build 限定 4 条），含 band/clip、anchor/scroll、页面进度、组变换、窗口坐标和时钟开关，不含歌词文字。若仍上闪，请同时提供使用的版本、时钟开关状态、是否启用 HDR、同一次动作的这些日志及短录屏。

导航背景交接诊断：`navigation background handoff restore=`；地图取色沿用 `MCLyricContrast`。胶囊结构与落地轨迹可沿用模块已有 `op mini` 诊断。没有声称已经完成真机验证。
