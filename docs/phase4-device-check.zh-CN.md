# 第四轮：歌词实际入口与绘字反馈

第三轮 Plus3 云构建通过后，用户真机反馈歌词仍未出现。此前只修正独立歌词页的显示进度，不能视为歌词链路已经通过真机验收。本轮继续修复实际入口，保留已由用户确认正常的导航图标、TTML／和声、外观与来源设置。

## 源码确认的问题及处理

| 环节 | 问题与修改 | 主要文件 |
| --- | --- | --- |
| 实际歌曲身份 | 原点按入口把缓存的 `sTrackKey` 直接交给歌词；手动模式、尚未自动进入封面或自动入口被抑制时，此键可能为空／过期。`lyricKey()` 又在缓存键为空时提前返回，尚未读取有效 MediaMetadata 就跳过加载。现在使用胶囊当前绑定的 MediaController 与实时歌曲身份；歌词自身也能从元数据生成身份，并保留播放器把逐行歌词放入 TITLE 时的稳定键策略。 | `Main.java`、`lyrics/LockLyrics.java`、`lyrics/LyricTrackKey.java` |
| 后续换歌／背景重建 | 手动模式下，视频背景重建还会经 `detachCover()` 注销刚绑定的会话监听；现在胶囊请求／过渡期间保留订阅，真正结束会话时清理。旧元数据处理在自动封面关闭或入口被抑制时提前返回，点按打开的歌词收不到换歌。现在在这些封面专用门控之前更新已请求的歌词。 | `Main.java` |
| 背景／封面一致性 | 原独立入口只请求歌词和单独占用时钟，没有进入原有背景场景，背景初始化与歌词模糊未走正常链路。现在复用 `setCoverEnabled → enterCoverMode`，保留当前背景样式、保留壁纸、视频／图片封面、歌词模糊和 HDR 设置。不会替用户改总开关、自动开关或样式；封面总开关关闭时只显示原有壁纸上的歌词。 | `Main.java`、`lyrics/LockLyrics.java`、`KeepDim.java`、`LockHold.java` |
| 胶囊与详细卡片 | 背景处于封面场景不再等于必须展开媒体卡。点按保持胶囊，真正完成上滑才移交给原卡片入口；多胶囊预备布局不提前移交，取消、布局等待超时或启动失败时保留原状态。 | `island/MiniPlayerController.kt`、`island/MiniPlayerRuntime.kt`、`island/MiniPlayerPresentationPolicy.kt` |
| 判断实际绘制 | 点击请求不能证明歌词已渲染。新增立即及 250 ms、1.5 s、5 s 的有限诊断，区分歌曲键、加载状态、来源、行数、窗口、时钟、页面进度、附着、布局区间和透明度。新点按、关闭或移交取消上一组跟进；不记录歌曲、歌词正文，不增加常驻重试循环。 | `lyrics/LockLyrics.java`、`lyrics/LyricView.java` |

这些是可从代码确认的缺口；当前环境仍无法确认用户设备上的最终阻断点是否全部消除。若数据加载、系统容器或布局仍被设备特定行为阻断，应根据本轮诊断继续定位，不能以反馈动画出现当作验收。

## “词”与叉号动画

- 开启：真实字体的“词”从左上角向右下方逐渐显出，不模拟严格笔顺。绘制 320 ms，完整停留 **300 ms**，再用 180 ms 恢复实时播放／暂停图标。
- 关闭：从当前画面恢复完整“词”（120 ms），在字上依次绘出两条叉线（240 ms），完整停留 300 ms，180 ms 恢复播放图标。
- 任意阶段可反向切换，保留当前几何位置和透明度；单一时间线与代次令牌取消旧更新／结束回调。歌词请求立即切换，不等待动画。
- 使用 ValueAnimator 随系统动画时钟绘制，提示期间只为该按钮申请高刷新率，完成、隐藏、失焦、移除或显示器进入熄屏／AOD 后恢复先前刷新率请求并清理监听。最终刷新率由屏幕能力和系统功耗策略决定，不承诺强制突破系统限制。参见 [Android 自适应刷新率](https://developer.android.com/develop/ui/views/animations/adaptive-refresh-rate)。
- 不更换真实播放 drawable，提示结束后绘制当时绑定的播放状态；按压仅缩放视觉内容，最低仍为 0.65，触摸区域不变。

实现位于 `island/PressFeedbackButton.kt`、`island/CapsuleFeedbackState.kt`；状态测试覆盖绘制方向、完整停留时长、关闭叉号、快速反向、渐退中打断、清理及到期恢复。

## 真机验收

1. 用同一首确定有歌词的歌曲，分别测试手动／自动封面模式。点按音乐胶囊主体应立即请求并实际显示歌词，再点隐藏；播放按钮只控制播放，上滑仍打开原媒体卡。
2. 对照同一设置下原入口的图片、视频、保留壁纸背景、模糊和 HDR；点按不得自行切换背景样式。封面总开关关闭时不能擅自开启封面。
3. 测试首个播放会话、元数据晚于胶囊出现、换歌、换播放器、熄屏唤醒和锁屏视图重建；自动封面曾关闭后歌词仍应跟随当前歌曲。
4. 先用双指隐藏歌词后再点按，应重新显示；再正常关闭时应能退出本次打开的背景。分别在只有音乐、音乐旁有导航／其他胶囊时测试：上滑完成、拖到一半返回、手势取消；取消后应保持原歌词及胶囊状态，不能误展开卡片。
5. 在绘字、完整停留、画叉及渐退各阶段快速反向点击；歌词最终状态与最后一次请求一致，播放图标反映真实播放状态。关闭屏幕／进入 AOD 后不可残留提示或长期维持动画高刷请求。
6. 导航图标保持已验收颜色；既有 TTML 和声、普通 LRC、联网关闭、来源回退与同目录格式设置做回归抽查。

若仍不显示，请提供这次操作前后约 5 秒的模块日志（`capsule lyrics request`、`capsule visibility`、`lyricstate`），注明播放器与版本、系统版本、音乐独占还是多胶囊，以及同一歌曲上滑后的实际结果。附当前背景样式、封面自动开关、歌词／HDR 开关即可；不需要歌词正文、账号或通知正文。诊断中 `lines=0`、`pageProgress=0`、`band=none`、`show=0`、容器透明度分别指向不同链路。

## 本功能中文 PR 描述草稿

音乐胶囊点按在手动封面模式下可能只显示提示动画：缓存歌曲键尚未建立就跳过歌词加载，独立入口也绕过原背景初始化。现在从当前媒体会话读取歌曲身份，复用原封面场景及其背景设置，并把背景显示与媒体卡展开状态分开。点按切换歌词，上滑完成才展开媒体卡，取消手势保持当前页面。

反馈改为从左上角逐渐绘出“词”，关闭时在字上绘出叉号，完整停留 300 ms；支持随时反向，恢复当前播放状态，隐藏／熄屏时释放临时动画与高刷请求。增加歌曲身份、页面进度、展示策略和动画中断回归及有限的实际绘制诊断。真机验收结果待用户补充后再提交。
